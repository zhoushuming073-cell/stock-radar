# 9. Logging convention from now on

To prevent status from fragmenting again:

1. Every journey log uses `journey-YYYY-MM-DD-HHMM-<emoji><status>.md`.
2. `HHMM` uses the GitHub repository commit timestamp in UTC so historical filenames are deterministic.
3. Status vocabulary is fixed: `📌当前总账`, `✅已完成`, `🟡部分完成`, `❌未完成`, `🗂️历史归档`, and `🧭路线图`.
4. Exactly one journey file may be `📌当前总账`. `reports/README.md` points to it.
5. When a new canonical snapshot is published, create a new timestamped `📌当前总账` journey and rename the previous canonical file to `✅已完成` or `🗂️历史归档`, according to its role.
6. Closed bug backlogs and fix-pass records remain preserved as `✅已完成`; they are not reused as task lists.
7. Mixed historical planning notes become `🗂️历史归档`; optional future adoption plans use `🧭路线图`.
8. `🟡部分完成` and `❌未完成` are allowed only when a standalone historical log genuinely remains actionable; current work should still be consolidated into `📌当前总账`.
9. `reports/phase2/` remains historical research evidence rather than journey status logs.
10. `docs/` contains contracts/specifications, not current task status.
11. Every journey file must carry a visible status banner at the top matching its filename.
