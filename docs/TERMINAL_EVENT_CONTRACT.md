# Terminal events and formal PIT gate

`data/terminal-events.csv` and `data/terminal-events-manifest.json` are optional local imports. No external terminal dataset is bundled. The manifest must identify its provider, source version, coverage start/end, `coverage_complete: true`, and all `event_types_covered`. This is a **source attestation**. Stock Radar verifies the file structure, interval, identity mapping and bar coverage; it cannot prove that the provider supplied every real-world event.

CSV columns: `security_id,event_date,event_type,terminal_value_type,cash_per_share,stock_exchange_ratio,successor_security_id,final_trade_price,currency,known_complete,notes`. Every event needs a stable security ID, date, supported type and `known_complete=true`. The supported types are `cash_acquisition`, `stock_merger`, `delisting`, `bankruptcy`, `liquidation`, `ticker_change`, and `unknown_terminal_event`. A ticker change must preserve `security_id` and does not terminate the investment.

Version `terminal-cash-v1` values **only** an explicit USD `cash_acquisition` with `terminal_value_type=cash_per_share` and a finite nonnegative `cash_per_share`. Other currencies require a separately sourced FX policy and remain unvalued. It does not infer a value from `final_trade_price`, a missing bar, or a stock exchange ratio. Other terminal events are unvalued until a separately versioned policy supports them. Scanner `scanner-forward-v3-terminal` computes primary outcomes from observed OHLC followed by the cash settlement as a point value; it does not fabricate a high/low bar or an MFE/MAE for the missing horizon. Ambiguous observed same-session target/adverse touches remain censored. Without a terminal import, historical Scanner labels retain `scanner-forward-v2` semantics.

For PIT Backtest, a held security with a missing eligible mark is settled only when its stable `security_id` has a sourced cash event at that date. Settlement has no simulated market sell/slippage fee. An unvalued event raises `unresolved-terminal-position`; a missing mark without an event fails explicitly. Existing Current Snapshot run behavior is unchanged.

`GET /api/lab/pit-readiness?split=validation` reports the Security Master and terminal provenance, eligible security/session bar counts, terminal event counts, source attestation, structural verification, and Scanner censoring audit. The System page displays the same report. `formal_pit_ready=true` means all *installed* source claims and software checks passed; the validity level remains `formal_pit_source_dependent`. A trustworthy external provider and independent due diligence are still needed before claiming unbiased historical results.

Synthetic tests exercise the import, coverage gate and policy. They do not establish completeness of any vendor dataset.
