# Stock Radar 项目评估方案书

> **用途：** 本文档用于 Stock Radar 后续阶段评估、课程/答辩评审和项目成熟度复核。  
> **性质：** 这是评估标准，不是项目当前成绩，也不是投资建议。  
> **原则：** 不以“回测收益率高低”单独决定项目质量；学术研究价值、金融投资价值、技术工程价值必须分别判断。  
> **评估时点：** 每次正式评估都应冻结代码版本、数据版本、参数合同与证据范围，并记录 Git commit SHA。  
> **当前项目定位说明：** 截至本文档建立时，Stock Radar 更接近“量化研究平台 + 策略研究系统”，仓库明确禁止券商下单，因此不应按已完成实盘交易系统进行评价。未来若项目边界变化，应在评估前重新确认。

---

## 1. 评估目标

最终必须形成三个**彼此独立**的结论：

1. **学生研究能力结论**  
   是否表现出扎实的学习能力、金融理解、科研方法、独立判断、问题定位与反思能力。

2. **策略投资价值结论**  
   策略是否存在可信、可解释、在现实交易约束下仍有可能成立的超额收益；若证据不足，应明确写“尚未证明”，而不是用工程完成度替代投资有效性。

3. **量化系统工程结论**  
   数据、研究、回测、执行模拟、审计、测试和复现链路是否可靠，系统是否真正实现设计目标。

一个项目可以是优秀的学术/工程作品，但暂时不具备可信投资价值。三类结论不得互相代替。

## 2. 100 分评分体系

| 维度 | 分值 | 核心判断 |
| --- | ---: | --- |
| 1. 策略设计与金融逻辑 | 15 | 为什么理论上可能赚钱，是否存在可检验的投资假设 |
| 2. 数据质量与处理 | 15 | 数据来源、PIT 时点准确性、身份/退市/公司行动、偏差控制 |
| 3. 回测方法科学性 | 20 | 前视偏差、幸存者偏差、样本外、过拟合、稳健性与实验纪律 |
| 4. 投资绩效与基准比较 | 15 | 超额收益、风险调整后收益、基准与因子归因 |
| 5. 风险管理 | 10 | 回撤、集中度、尾部风险、组合暴露和压力测试 |
| 6. 交易可实现性 | 10 | 成本、滑点、流动性、成交假设、规则与执行约束 |
| 7. 系统工程能力 | 5 | 架构、测试、自动化、稳定性、可复现和审计能力 |
| 8. 学术研究与独立性 | 10 | 文献、原创贡献、失败实验、AI/开源使用透明度、反思能力 |
| **合计** | **100** | |

### 建议等级

| 总分 | 项目层次 | 解释 |
| --- | --- | --- |
| 90–100 | 专业型 / 高水平研究型 | 研究、投资验证与工程均较成熟，结论边界清晰 |
| 80–89 | 扎实研究型 | 方法较严谨，存在明确独立贡献，仍可能有局部证据缺口 |
| 70–79 | 完整型 | 项目结构完整，但研究可信度或投资验证仍有明显改进空间 |
| 60–69 | 基础合格 | 能完成较完整工程/研究流程，但关键结论尚不稳健 |
| <60 | 尚未达到可信评估标准 | 数据、方法、复现或研究纪律存在实质性缺口 |

> **注意：** 总分高不等于可以实盘；投资价值必须单独满足第 10 节的放行条件。

## 3. 红线项与评分上限

以下问题不能被漂亮 UI、高收益率或大量测试数量抵消。

### R1. 影响核心结论的未来数据泄漏 / Look-ahead Bias

若确认存在且尚未修复：

- “策略投资价值”直接判定为 **不成立 / 不可评估**；
- 第 3 项“回测方法科学性”原则上不得高于 6/20；
- 在修复并重新冻结数据、重新运行实验前，不得引用受污染收益作为成绩。

### R2. 核心结果无法复现

若无法从固定版本重新得到关键研究结果：

- 第 7 项“系统工程能力”不得高于 2/5；
- 第 8 项“学术研究与独立性”不得高于 5/10；
- 总分原则上不高于 69，直至复现链恢复。

### R3. 将模拟、探索性结果或未验收结果宣传为实盘收益/正式 Alpha

若发生：

- 视为研究诚信问题；
- 必须单独记录并要求纠正；
- 学术研究与独立性可大幅扣分；
- 未纠正前不得给出“专业型”评价。

### R4. 幸存者偏差或证券身份错误足以改变结论

若历史股票池、ticker reuse、退市证券、公司行动等问题仍可能实质改变核心排名或组合结果：

- 允许继续进行明确标注的 exploratory research；
- 不允许把相关回测写成“已证明的历史投资表现”；
- 第 2、3、4 项必须反映该限制。

## 4. 各维度详细评分标准

## 4.1 策略设计与金融逻辑 — 15 分

评估重点不是“用了多少指标/算法”，而是投资假设是否有金融逻辑且可证伪。

### 必查问题

- 策略属于趋势、动量、均值回归、事件驱动、多因子、统计套利还是其他类型？
- 收益来源假设是什么：风险溢价、行为偏差、流动性补偿、市场结构、信息处理速度，还是其他机制？
- 股票池为什么这样定义？
- 信号频率、持有期、成交时点是否与假设一致？
- 新增复杂模型究竟改善了什么：预测力、回撤、排序稳定性、校准，还是执行质量？
- 若使用价格形态语言，能否将主观描述拆成明确、可测量、可反驳的特征？

### Stock Radar 专项

当前核心研究方向强调“强势主升 → 回撤 → 下跌动能衰竭 → 承接 → 初步转强”的形态量化。正式评估时应要求学生说明：

- 每一个主观概念如何映射为因果特征；
- 为什么这些特征理论上可能形成未来收益差异；
- 各特征是独立贡献还是同一动量/波动暴露的重复表达；
- Strategy 2 相比传统动量、回撤反转或简单技术筛选基准的新增价值。

### 评分参考

- 13–15：金融逻辑清楚、可证伪、有独立研究问题，并能解释失败情形。
- 9–12：逻辑基本合理，但部分规则主要来自经验或后验观察。
- 5–8：主要描述指标和代码，缺少明确经济机制。
- 0–4：核心逻辑仅为“历史上回测赚钱”。

## 4.2 数据质量与处理 — 15 分

量化研究中，数据可信度优先于模型复杂度。

### 必查内容

- 数据来源、许可、覆盖区间、频率、更新时间和版本。
- 缺失值、异常价、停牌、零成交、交易日历处理。
- raw / adjusted 价格口径是否混用。
- 拆股、现金分红、并购、退市、ticker rename / reuse 的处理。
- 决策时点是否只使用当时可获得的信息。
- 历史股票池是否包含后来退市/改名/剔除证券。
- 多数据源之间的日期、证券身份与价格口径冲突如何解决。
- 数据版本是否可以冻结并重新构建。

### Stock Radar 专项

评估应重点核对：

- PIT security master；
- 历史 membership；
- security identity / ticker reuse；
- delisted / terminal event；
- split / dividend / merger；
- Research-Grade 与 Formal PIT 的边界；
- QuantConnect / 本地来源之间的独立验证结果。

主要证据入口应从以下文件开始：

- `reports/journey-2026-09-30-0651-📌当前总账.md`
- `reports/README.md`
- `docs/PIT_SECURITY_MASTER.md`
- `docs/PIT_LEAN_DATA_DESIGN.md`
- `reports/acceptance/`
- `reports/evidence/`
- `reports/audit/`

### 评分参考

- 13–15：关键研究人口、身份、价格和事件均有 PIT 边界与可审计证据。
- 10–12：主体可信，但仍有明确且量化过的覆盖缺口。
- 6–9：数据可用，但偏差控制不充分或来源/口径解释不足。
- 0–5：当前名单回填历史、未控制未来信息或数据来源不明。

## 4.3 回测方法科学性 — 20 分

这是权重最高的评估维度。

### 必查内容

- Train / Validation / Test 或其他冻结研究窗口是否事前定义。
- 是否存在真正未被反复查看的独立样本外数据。
- 是否采用 walk-forward / rolling validation。
- 是否在 Test/OOS 上反复调参。
- 是否存在大量策略/参数搜索后只报告最好结果的问题。
- 成本、滑点、成交时点、持有期是否符合现实。
- 是否覆盖多种市场状态。
- 参数变化 10%–20% 时结果是否稳定。
- 是否进行 missingness、universe、成本、执行延迟、极端行情压力测试。
- 是否将 Scanner 诊断结果与完整投资组合收益混为一谈。

### Stock Radar 专项

必须区分至少四类证据：

1. Scanner 前瞻标签结果；
2. Current / exploratory 回测；
3. Research-Grade PIT；
4. Formal PIT / Native LEAN。

任何一层的 PASS 都不得自动升级为下一层 PASS。

Strategy 2 的研究评估应至少报告：

- Precision@K / Lift@K；
- MFE / MAE；
- time-to-target；
- False Falling-Knife 比例；
- 年份/波动/牛熊环境分层；
- 参数敏感性；
- universe / identity / missingness sensitivity；
- 新鲜 OOS 或 walk-forward 结果（若尚无，则必须明确标记缺失）。

### 评分参考

- 17–20：研究窗口冻结、PIT 较完整、OOS/滚动验证充分、稳健性测试系统化。
- 13–16：方法基本可靠，但 OOS 或 PIT 仍有有限缺口。
- 8–12：主要依赖一次历史回测或存在较强研究者自由度。
- 0–7：存在严重泄漏、后验调参或不可复现。

## 4.4 投资绩效与基准比较 — 15 分

收益率必须和风险、基准、因子暴露一起评价。

### 最低指标集合

- CAGR
- Sharpe Ratio
- Sortino Ratio
- Max Drawdown
- Calmar Ratio
- Beta
- Alpha（使用清楚说明的风险模型）
- Turnover
- 交易次数、持仓集中度
- 年度/市场状态分解

### 必须比较的基准

根据投资范围选择合理组合，不机械要求所有策略只对 SPY：

- SPY 总收益；
- QQQ（若成长/科技暴露明显）；
- eligible universe 等权或市值权重；
- 简单 buy-and-hold；
- 一个最接近策略逻辑的简单规则基准，如传统动量/回撤反转。

### 收益归因

必须回答所谓 Alpha 是否主要来自：

- 市场 Beta；
- 科技/成长；
- 小市值；
- 动量；
- 高波动；
- 行业集中；
- 杠杆；
- 极少数异常赢家。

建议至少提供：

- 去掉收益最好 5 笔后的结果；
- top contributors concentration；
- factor / sector / beta exposure；
- 分年份超额收益。

### 评分参考

- 13–15：有稳定、风险调整后的样本外超额收益，且归因后仍能说明独立价值。
- 9–12：表现有一定优势，但统计稳定性、OOS 或风险归因仍不足。
- 5–8：绝对收益好看，但优势大部分可由基准/风险暴露解释。
- 0–4：只展示累计收益或选择性展示最佳区间。

## 4.5 风险管理 — 10 分

### 必查内容

- 单股权重上限；
- 行业/主题集中度；
- 市场、成长、动量、小盘等因子暴露；
- 杠杆与现金管理；
- 流动性限制；
- 最大回撤；
- gap risk；
- 相关性突然上升；
- 极端行情与尾部场景；
- 风控规则本身是否经过独立验证，而非“感觉应该有用”。

### 答辩压力题

> 如果明天美股大跌 8%，当前策略最可能通过哪些路径亏损？哪些平时成立的假设会失效？

优秀回答不要求预测准确，但要能识别风险传导路径。

---

## 4.6 交易可实现性 — 10 分

### 必查内容

- 佣金与交易相关费用；
- Bid-Ask Spread；
- slippage；
- 开盘/收盘成交假设；
- gap；
- 流动性与成交量参与率；
- 市场冲击；
- 停牌与无成交；
- 若做空：borrow availability / borrow fee；
- 交易时段、日历、账户与结算约束；
- 模拟引擎与真实券商行为差异。

### Stock Radar 专项

项目当前明确不向券商发送订单，因此本项评价的是“研究结果是否具备现实可执行性建模”，不是“是否已经实盘”。

若未来加入实盘，再增加：

- pre-trade risk checks；
- order state reconciliation；
- duplicate-order protection；
- kill switch；
- broker/API outage recovery；
- partial fill / reject / cancel handling。

---

## 4.7 系统工程能力 — 5 分

### 必查内容

- 数据获取与更新管道；
- 配置与参数冻结；
- 策略插件/信号生成；
- 回测与 LEAN 接入；
- 运行状态、日志与错误处理；
- 单元/集成/回归测试；
- 固定输入 → 固定结果的复现能力；
- Git 版本和报告证据关联；
- 本地数据、生成物和仓库源码边界；
- 审计链是否能解释“为什么这个结果可信”。

### 注意

“测试数量很多”本身不等于工程质量高。应检查测试是否覆盖真正的错误模式和研究风险。

---

## 4.8 学术研究与独立性 — 10 分

### 必查内容

- 是否查阅并理解相关学术/行业文献；
- 能否说明自己与经典动量、反转、因子研究的关系；
- 是否报告失败实验；
- 是否记录参数选择过程；
- 是否主动揭示研究限制；
- 是否能在没有 AI 代答时解释核心模块；
- 哪些工作来自本人设计、开源项目、成熟框架或 AI；
- 使用 AI 后是否能验证、修改、反驳 AI 生成内容。

### AI 使用评估原则

使用 Codex、ChatGPT 或其他 AI **不自动扣分**。重点是：

- 学生是否保有研究决策权；
- 是否理解关键实现；
- 是否能识别 AI 错误；
- 是否有 evidence / tests 验证生成代码；
- 是否透明说明 AI 在项目中的角色。

若 AI 能完成代码，但学生无法解释核心假设和实验设计，则不能给高独立性评分。

## 5. 正式评估流程

一次正式评分建议按以下顺序执行。

### Stage 0 — 冻结评估对象

记录：

- Git commit SHA；
- Strategy / plugin version；
- config / parameter hash；
- 数据版本与时间范围；
- universe 定义；
- evaluation window；
- 关键 evidence 文件；
- 环境版本。

冻结后不得因为看见结果而悄悄调整规则。

### Stage 1 — 研究问题与金融逻辑答辩

学生用不超过 10 分钟说明：

1. 研究问题；
2. 策略为什么可能有效；
3. 与简单基准相比创新在哪里；
4. 当前最重要的未解决风险是什么。

### Stage 2 — 数据与 PIT 审计

从 canonical ledger 开始，沿 acceptance → evidence → docs → code 检查：

- 数据来源；
- 证券身份；
- membership；
- corporate actions；
- terminal events；
- price coverage；
- point-in-time 可得性。

禁止只凭 README 摘要判定 PASS。

### Stage 3 — 复现核心研究

至少选择一个固定评估入口，在干净环境中重跑：

- 一个代表性 Scanner 研究；
- 一个核心 backtest / LEAN execution；
- 一个关键 PIT/readiness audit；
- 关键指标生成。

必须记录命令、输入、版本、输出 hash 与结果差异。

### Stage 4 — 稳健性与投资评估

执行：

- benchmark comparison；
- cost ×2；
- parameter ±10% / ±20%；
- 去掉 top 5 trades；
- market regime split；
- missingness / universe sensitivity；
- exposure attribution；
- stress tests。

### Stage 5 — 答辩

使用第 8 节问题，不允许只展示 PPT。

### Stage 6 — 三结论 + 总分

先分别写研究、投资、工程结论，再填写 100 分量表。不得先决定总分再倒推子项。

## 6. 评估所需材料

正式评估前至少准备以下材料：

| 材料 | 最低内容 |
| --- | --- |
| 项目研究报告 | 研究问题、金融假设、文献、方法、结果、局限 |
| 系统架构图 | 数据 → 特征 → Scanner → Strategy → LEAN/Backtest → Evidence |
| 数据说明书 | 来源、版本、时间覆盖、身份、复权、缺失、许可和限制 |
| 完整回测报告 | 收益、风险、基准、成本、暴露和分阶段结果 |
| 稳健性报告 | OOS、walk-forward、参数、成本、市场状态、缺失敏感性 |
| 复现说明 | 固定 commit / config / data / command / expected output |
| 项目演示 | 从数据/研究入口到结果与证据链，不要求真实下单 |
| AI / 开源贡献说明 | 哪些内容由学生、AI、第三方框架分别完成 |

Stock Radar 已有的 canonical ledger、acceptance、evidence 与 docs 可以作为上述材料的一部分，但最终评估仍应检查其与实际代码/运行结果是否一致。

## 7. Stock Radar 专项证据矩阵

正式评审时，可按下表逐项填充当前证据。

| 研究主张 | 必须存在的证据 | 当前评估结果 |
| --- | --- | --- |
| Scanner 能富集目标走势 | Precision/Lift、MFE/MAE、基线命中率、时间分层 | 待评估 |
| Strategy 2 有独立投资价值 | OOS 组合结果、基准、风险调整指标、归因 | 待评估 |
| 不依赖未来信息 | as-of contract、特征时间戳、执行时点测试 | 待评估 |
| 无重大幸存者偏差 | PIT membership、身份、退市、未知竞争者敏感性 | 待评估 |
| 公司行动处理可靠 | split/dividend/merger/terminal evidence + tests | 待评估 |
| LEAN 执行结果可信 | frozen input、native execution、reconciliation | 待评估 |

## 8. 答辩重点问题

### Q1
**你认为这个策略为什么能赚钱？**

检查是否能讲金融机制，而不是重复算法流程。

### Q2
**如果直接买入 SPY、QQQ 或一个简单动量组合，结果会有什么不同？**

检查是否真正识别 Alpha，而不是 Beta/风格暴露。

### Q3
**回测中有没有任何数据在决策时点其实还不可获得？**

要求具体说明数据发布时间、特征时点和订单时点。

### Q4
**如果去掉收益最高的 5 笔交易，核心结论还成立吗？**

检查收益是否由极少数异常事件驱动。

### Q5
**参数整体变化 10%–20% 后，结果会不会发生根本变化？**

检查策略是否处于参数尖峰。

### Q6
**为什么选择当前 Train / Validation / Test 时间范围？**

检查是否人为选择最有利市场区间。

### Q7
**如果交易成本和滑点提高一倍，策略还有投资价值吗？**

检查 edge 是否足够厚。

### Q8
**如果再给三个月，你只允许优先解决一个问题，会选什么？为什么？**

检查是否真正理解当前瓶颈。

### Stock Radar 加问 Q9
**当前 Formal PIT、Research-Grade PIT、Scanner diagnostics 和 Native LEAN 分别证明了什么，又分别没有证明什么？**

检查学生能否严格区分证据层级。

### Stock Radar 加问 Q10
**Strategy 2 的优势如果最终消失，你认为最可能是哪一个研究假设被证伪？**

检查是否具备真正的科研反思能力。

## 9. 建议的现场演示

建议在答辩现场随机指定一个历史日期，而不是让学生只演示预先准备好的最好案例。

学生应能够：

1. 说明该日可用 universe；
2. 说明关键证券身份和价格来源；
3. 生成当日候选；
4. 展示信号为什么满足策略条件；
5. 展示未来标签只用于评估而非信号构造；
6. 运行或展示对应的 frozen LEAN / backtest 输入；
7. 找到对应日志、evidence、hash 或测试；
8. 解释任何 BLOCKED / PARTIAL 状态。

这比单纯播放一个 UI 演示更能判断实际掌握程度。

## 10. “具有投资价值”的额外放行条件

项目总分高并不自动意味着策略有可信投资价值。

建议只有同时满足以下条件，才允许在最终结论中写：

> “目前存在初步/较强证据支持策略具有投资价值。”

最低条件：

- 无未解决的重大 look-ahead；
- PIT / universe 问题已证明不会实质改变核心结论，或已纳入可信敏感性范围；
- 有真正独立的 OOS / walk-forward 证据；
- 风险调整后优于匹配基准；
- 成本、滑点、流动性后 edge 仍存在；
- 收益不是由极少数交易主导；
- 参数不存在明显尖峰；
- 主要风险暴露得到解释；
- 核心结果可复现；
- 当前证据状态不是 `BLOCKED`。

若任一关键条件不满足，应使用：

> “研究/工程具有价值，但尚未证明可部署的投资 Alpha。”

## 11. 当前项目类型的评估口径

Stock Radar 不应被强行归入单一类别。建议采用：

- **主要类型：策略研究型**
- **次要类型：量化交易平台型 / 金融科技工程型**
- **当前不是：已完成实盘交易型**
- **当前不以 AI/ML 模型为核心评价对象，除非未来正式加入机器学习预测层**

因此，评分时应将“研究科学性”和“数据可信度”放在系统 UI 或交易功能之前。

## 13. 最终评审原则

最终评价应优先回答：

> **这个学生是否知道自己“证明了什么”和“还没有证明什么”？**

对于本科阶段项目，一个结果并不惊艳、但研究过程严谨、敢于保留 BLOCKED/PARTIAL、能够定位失败原因并建立可复现证据链的项目，学术价值可以非常高。

相反，若项目只展示高收益率，却无法解释数据来源、证券身份、未来数据、样本外边界和风险暴露，则无论界面多完整、代码量多大，都不应获得高水平量化研究评价。
