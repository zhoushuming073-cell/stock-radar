# Stock Radar 策略插件使用说明

适用范围：当前本地版 Scanner Research v1.5；插件接口版本仍为 `1`。行情数据、密钥、候选快照和回测结果保存在本机。

## 先选你要做的事

| 目标 | 做法 |
| --- | --- |
| 只改阈值、候选数量或止损 | 在 Strategy Lab 的「策略参数」中编辑，然后启动一次新运行；不用复制 `strategy.py`。 |
| 改筛选条件、评分公式或排序方式 | 从现有模板复制一个新策略，编辑下面五个文件，打成 ZIP 导入。 |
| 研究每天筛出的股票是否有价值 | 运行 **Scanner Research**。它不建仓，不计算组合收益。 |
| 检查买卖、持仓、收益和回撤 | 运行 **Strategy Backtest**。回测功能仍在。 |

## 打开本地应用

在项目根目录双击 [启动本地看板.cmd](../启动本地看板.cmd)。它会启动或复用本地服务，并打开：

- [Streamlit 策略实验室](http://127.0.0.1:8502/)：进入 Strategy Lab，可切换「Scanner Research / Strategy Backtest」。
- [本地网页实验室](http://127.0.0.1:4174/lab.html#scanner)：Scanner 页面；切到 Strategy Lab 页面可做组合回测。

电脑关机或本地服务未启动时，网页无法读取本机数据。首次使用需要先按 [中文 README](../README.zh-CN.md) 安装项目的 `.venv` 环境。

## 最快上手：只调整已有策略

1. 打开 Strategy Lab，选中一个已安装的策略。项目自带 `full_strategy2_v1` 和示例模板。
2. 在「策略参数」编辑阈值。例如 `exit.stop_loss: -0.20` 表示模型止损阈值为亏损 20%；`null` 表示关闭该项自动退出。止盈 `take_profit` 用正数，例如 `0.05` 为 +5%；`max_holding_sessions` 是交易日数。
3. 选择下方的研究模式，点击运行。每次运行会保存自己的参数和结果，旧结果不会被覆盖。

请区分「每日期望候选数」与「持仓数」：前者限制 Scanner 展示/入选的候选数量，组合回测还会另按资金、流动性及持仓上限决定实际买入。

## 写一个新插件

从 [策略模板](../templates/strategy_plugin_template/) 复制一个目录，改名为纯英文小写下划线 ID，例如 `my_pullback`。目录只能有以下五个文件：

```text
my_pullback/
├── manifest.yaml
├── strategy.yaml
├── strategy.py
├── README.md
└── tests/
    └── test_strategy.py
```

1. **`manifest.yaml`**：设置显示名、唯一的 `id: my_pullback`、`version: 1.0.0`、作者和 `required_features`。`interface_version` 保持 `1`。目录名必须与 `id` 一致。策略 Python 中读取的每一个特征，都要同时列在这里和 `required_features()`。
2. **`strategy.yaml`**：设置可编辑阈值、`selection.max_candidates`、`evaluation` 和 `exit`。例如 `exit.stop_loss: -0.20`；`null` 可关闭止盈、止损或最长持有自动退出。普通数值微调只需生成新运行，不必复制 Python 文件。
3. **`strategy.py`**：定义一个 `StrategyPlugin` 子类，并在文件末尾导出 `PLUGIN = MyStrategy()`。实现四个方法：

   | 方法 | 作用 | 返回值 |
   | --- | --- | --- |
   | `required_features()` | 声明所需的因果特征 | `set[str]` |
   | `hard_filter(context, config)` | 每日剔除不合格股票 | 与 `context.frame` 同索引的布尔 Series |
   | `score(context, config)` | 给每只股票评分，越大越靠前 | 同索引的数值 Series |
   | `select(candidates, config)` | 从合格股票中按确定的顺序挑选 | 原候选的子集 DataFrame |

   可选的 `diagnostic_scores(context, config)` 能输出分项评分和 `p_*` 概率，供 Scanner 保存与评估。模板中的 [strategy.py](../templates/strategy_plugin_template/strategy.py) 已有完整可运行示例。
4. **`README.md`**：写清筛选条件、评分依据、参数含义和适用范围。
5. **`tests/test_strategy.py`**：覆盖阈值边界、缺失值、同分排序、空候选和重复运行结果一致性。可从 [模板测试](../templates/strategy_plugin_template/tests/test_strategy.py) 改起。

插件在信号日收盘后运行，只能看到当日的 `context.signal_date` 和 `context.frame`。它不能读取未来 K 线、未来收益、数据库、文件或网络，也不能下单。可用特征与完整接口见 [技术规范](STRATEGY_PLUGIN_SPEC.md)。逻辑或参数含义发生变化时递增插件版本号；仅调整参数数值则保留插件版本，用新运行记录差异。

### 打包与导入

先在策略目录运行自己的测试，再打包：

```powershell
Push-Location .\my_pullback
& ..\.venv\Scripts\python.exe -B -m pytest -q -p no:cacheprovider tests/test_strategy.py
Pop-Location
```

随后在项目根目录执行下面的 PowerShell 片段。它只打包规定的五个文件，避免把测试缓存或数据放进 ZIP：

```powershell
$code = @'
from pathlib import Path
from zipfile import ZipFile, ZIP_DEFLATED

folder = Path("my_pullback")
files = ["manifest.yaml", "strategy.yaml", "strategy.py",
         "README.md", "tests/test_strategy.py"]
with ZipFile("my_pullback.zip", "w", ZIP_DEFLATED) as archive:
    for name in files:
        archive.write(folder / name, arcname=f"{folder.name}/{name}")
'@
& .\.venv\Scripts\python.exe -c $code
```

ZIP 内必须只有一个顶层策略目录，且目录名等于 `manifest.yaml` 中的 `id`。界面接受不超过 5 MB 的 ZIP；导入时会检查文件结构、代码、可用特征、输出契约和插件测试。**只导入自己编写或信任的 Python 插件**；检查不能把任意插件变成安全沙箱。

在 8502 点击「＋ Import Strategy」→ 选择 ZIP →「验证并导入」。在 4174 点击「＋ Import Strategy」选择 ZIP。成功后选中新策略并检查参数。若导入失败，界面会显示具体原因；先核对目录名、ID、所需特征和测试结果。

## 运行 Scanner Research

选策略、训练期或验证期、每日候选数（Top 5/10/20 或全部），点击「运行 Scanner」。完成后可按交易日查看候选、排名、分项评分，以及未来十个交易日的统计标签。主要指标包括 Precision@K、相对同日合格股票池的 Lift@K、MFE/MAE、下跌延伸率与市场状态拆分。

Scanner 的主目标默认是未来十个交易日内价格是否触达 +5%。以次一交易日开盘价为参考，未来日线 High/Low 用于事后标签；同一天内先涨后跌的顺序未知，因此这些指标**不是可直接成交的收益率**。数据末尾不足十个完整交易日的候选会显示，但不计入完整标签的命中率。

## 运行组合回测

切换到 **Strategy Backtest**。可以选择训练期、验证期或历史测试期，并设置滑点：

- 「单阶段运行」只跑所选时段。
- 「三阶段逐日回测」依次跑训练、验证、测试，按交易日推进权益曲线和持仓画面。三个阶段分别重置资金与持仓；可选播放间隔。
- 运行记录会显示收益、回撤、每天的持仓、成交、退出原因与生效的止盈止损参数。历史运行保留，可比较或克隆参数后再跑新版本。

当前新运行在信号日收盘后选股，最早于下一有效交易日开盘模拟买入；具体能否买入还受跳空、现金、流动性和仓位约束。模型只使用日线数据，无法确定盘中事件先后顺序。历史测试期此前已被查看，适合回顾，不宜把反复调参后的结果当作全新的样本外证明。

## 常见问题

- **改了止损，还要重新导入 ZIP 吗？** 不需要。改界面参数并创建新运行；旧运行不变。
- **为什么 Scanner 有候选，回测却没买？** 候选排序与实际建仓是两步；组合引擎还有资金、仓位、跳空和流动性限制。
- **为什么 ZIP 被拒绝？** 常见原因是顶层目录与 `id` 不同、缺文件、多了缓存文件、所需特征未声明或插件测试失败。
- **策略能直接下单吗？** 不能。插件只输出候选；本项目当前没有券商下单路径。
